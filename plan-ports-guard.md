# Plan: Fixed Ports + PROD Guard

## Problem A: Port Drift
- Prod ports come from `~/.config/browser-os/.browseros/server_config.json` — auto-generated by AppImage on first run
- Dev ports come from `.env.development` + Go CLI `defaultLocalPorts`
- Neither is a single source of truth → drift on every redeployment

## Solution A: Single Port Manifest
Create `scripts/ports.sh` — ONE file that defines ALL port constants.

```
PROD:  9105 / 9200 / 9300  (fixed, written to server_config.json before launch)
DEV:   9010 / 9011 / 9012  (fixed, read by Go CLI + .env.development)
```

### Implementation:
1. Create `scripts/ports.sh` with shell variables for all 6 ports
2. `start-prod`: before launching AppImage, ensure `server_config.json` has the correct fixed ports. If the file exists with WRONG ports, rewrite it.
3. `.env.development`: generated from `scripts/ports.sh` values (or just hardcode matching values)
4. Go CLI `defaultLocalPorts`: hardcoded to match dev ports
5. All mise tasks source `scripts/ports.sh` for port values
6. Kill tasks use port-specific `fuser` (not pkill) to avoid cross-instance kills

## Problem B: PROD Kill Guard
- `kill-prod` happily kills prod even if user has active LLM sessions
- No warning, no safety net

## Solution B: Active Connection Check Before Kill
Before killing prod, check the health endpoint for active connections.

### Logic:
```
1. Is prod running? (check by profile path)
2. If yes: curl prod health endpoint
3. If health returns {"status":"ok"} AND cdpConnected=true:
   → User is actively using it. REFUSE to kill.
   → Print: "PROD is ACTIVE with connected browser. If you REALLY need to restart:"
   → Print: "  BROWSEROS_FORCE_KILL_PROD=1 mise run browseros:kill-prod"
   → Exit 1
4. If FORCE env var is set: skip check, kill anyway (with warning)
```

### Files changed:
- EDIT: `.mise/tasks/browseros/kill-prod`
- EDIT: `.mise/tasks/browseros/start-prod` (calls kill-prod internally, needs FORCE passthrough)
